## 一、性能优化金字塔

```
         ┌─────────────────┐
         │   算法复杂度     │  ← 最重要 (100x 提升)
         ├─────────────────┤
         │  数据结构选择    │  ← 重要 (10-100x)
         ├─────────────────┤
         │  内存布局优化    │  ← 中等 (2-10x)
         ├─────────────────┤
         │  编译器优化      │  ← 辅助 (1.2-2x)
         ├─────────────────┤
         │  微观优化        │  ← 最后手段 (1.1-1.5x)
         └─────────────────┘

原则：从上到下优化，不要过早优化底层！
```

## 二、十大性能优化技术（按影响排序）

### 1. 算法优化（最重要）

**案例：矩阵乘法**

```cpp
// ❌ O(n³) 朴素算法
for (int i = 0; i < N; ++i) {
    for (int j = 0; j < N; ++j) {
        for (int k = 0; k < N; ++k) {
            C[i][j] += A[i][k] * B[k][j];
        }
    }
}

// ✅ O(n³) 但缓存友好
for (int ii = 0; ii < N; ii += BLOCK) {
    for (int jj = 0; jj < N; jj += BLOCK) {
        for (int kk = 0; kk < N; kk += BLOCK) {
            // 分块处理
        }
    }
}
```

**提升**：11.9x（1024x1024 矩阵）

### 2. 数据结构选择

**F14 vs std::unordered_map**：

```cpp
// ❌ 慢
std::unordered_map<int, int> map;

// ✅ 快 2-4x
folly::F14FastMap<int, int> map;
```

**决策树**：

```
需求                          推荐结构
快速查找，小对象              F14FastMap
大对象，引用稳定              F14NodeMap
内存受限                     F14ValueMap
需要排序                      std::map (btree)
小数组（< 100 元素）          std::vector + 线性搜索
```

### 3. 内存分配优化

**Arena vs malloc**：

```cpp
// ❌ 多次 malloc
for (int i = 0; i < 1000000; ++i) {
    auto* obj = new Object();
    // ...
    delete obj;
}

// ✅ Arena 批量分配
folly::SysArena arena;
for (int i = 0; i < 1000000; ++i) {
    auto* obj = new (arena.allocate(sizeof(Object))) Object();
    // ...
}
// arena 析构时统一释放
```

**提升**：2.4-3x，减少 99.997% 系统调用

### 4. 避免伪共享（多线程杀手）

**问题代码**：

```cpp
struct Bad {
    std::atomic<int> a;  // 偏移 0
    std::atomic<int> b;  // 偏移 4 - 同一缓存行！
};
```

**优化方案**：

```cpp
struct Good {
    alignas(64) std::atomic<int> a;
    char padding1[64 - sizeof(std::atomic<int>)];

    alignas(64) std::atomic<int> b;
    char padding2[64 - sizeof(std::atomic<int>)];
};
```

**提升**：7x（并发递增测试）

### 5. SBO（小缓冲区优化）

**small_vector vs std::vector**：

```cpp
// ❌ 总是堆分配
std::vector<int> vec;
vec.push_back(1);  // malloc!

// ✅ 小对象栈上分配
folly::small_vector<int, 8> vec;
vec.push_back(1);  // 栈上，零开销
```

**提升**：1.8x（小数组）

### 6. 异步 I/O

**同步 vs 异步**：

```cpp
// ❌ 同步阻塞
void handle(int socket) {
    read(socket, buf, size);  // 阻塞整个线程
}

// ✅ 异步非阻塞
evb.registerHandler(socket, EV_READ, [] (int fd) {
    read(fd, buf, size);  // 事件驱动
});
```

**提升**：25x 吞吐量，90x 延迟降低（P99）

### 7. 分支预测优化

**使用 FOLLY_LIKELY**：

```cpp
// ❌ 无提示
if (data != nullptr) {
    // ...
}

// ✅ 标记热路径
if (FOLLY_LIKELY(data != nullptr)) {
    // 快速路径
} else {
    // 慢速路径（错误）
}
```

**提升**：10-15%

### 8. SIMD 向量化

**F14 的 SIMD 过滤**：

```cpp
// ✨ 同时比较 14 个键（SSE2/NEON）
__m128i tags = _mm_load_si128(chunk->tags);
__m128i target = _mm_set1_epi8(tag);
__m128i cmp = _mm_cmpeq_epi8(tags, target);
uint16_t mask = _mm_movemask_epi8(cmp);
```

**提升**：2-4x（vs std::unordered_map）

### 9. 零拷贝技术

**sendfile**：

```cpp
// ❌ 两次拷贝
read(file_fd, buf, size);
write(socket, buf, size);

// ✅ 零拷贝
sendfile(socket, file_fd, &offset, size);
```

**提升**：3x（文件传输）

### 10. 定时器优化

**HHWheelTimer vs 堆**：

```cpp
// O(1) 调度 vs O(log n)
folly::HHWheelTimer timer(&evb);
timer.scheduleTimeout(cb, std::chrono::milliseconds(1000));
```

**提升**：9x（调度），16x（tick）

## 三、性能优化决策树

### 场景 1：哈希表选择

```
开始
  ↓
元素大小 < 24 字节？
  YES → F14FastMap（默认最优）
  NO  ↓
需要引用稳定（迭代器不失效）？
  YES → F14NodeMap
  NO  ↓
内存受限？
  YES → F14ValueMap（节省内存）
  NO  → F14VectorMap（大对象优化）
```

### 场景 2：容器选择

```
数据量 < 100？
  YES → std::vector + 线性搜索
  NO  ↓
需要排序？
  YES → folly::F14VectorMap（有序键）
  NO  ↓
需要频繁插入/删除？
  YES → std::list（小心性能）
  NO  → F14FastMap（最快查找）
```

### 场景 3：内存分配

```
临时对象（生命周期短）？
  YES → Arena
  NO  ↓
小对象（< 1KB）？
  YES → jemalloc（默认）
  NO  ↓
大对象（> 1MB）？
  YES → mmap（直接分配）
  NO  → SysArena（线程本地）
```

### 场景 4：并发模型

```
单机多核？
  YES ↓
I/O 密集型？
  YES → EventBase（单线程多连接）
  NO  ↓
CPU 密集型？
  YES → 线程池（CPUExecutor）
  NO  → 混合模型
```

## 四、性能分析工作流

### 第一步：定位瓶颈

```bash
# 1. 使用 perf 找热点
perf record -F 99 -g ./your_program
perf report

# 2. 查看缓存命中率
perf stat -e cache-references,cache-misses ./your_program

# 3. 使用 valgrind 分析内存
valgrind --tool=cachegrind ./your_program
```

### 第二步：分类瓶颈

| 瓶颈类型 | 特征 | 优化方向 |
|---------|------|---------|
| CPU 密集 | 高 CPU 使用率，低 I/O | 算法优化、SIMD |
| 内存密集 | 高缓存未命中 | 内存布局、预取 |
| I/O 密集 | 高等待时间 | 异步 I/O、零拷贝 |
| 锁竞争 | 高上下文切换 | 无锁数据结构 |
| 分支失败 | 高 branch-misses | 分支提示 |

### 第三步：选择优化技术

根据瓶颈类型选择对应技术（参考十大技术）

### 第四步：验证提升

```bash
# 重新测量
perf stat -e cycles,instructions,cache-misses ./optimized_program

# 对比基准
hyperfine ./old_program ./new_program
```

## 五、常见反模式（避免！）

### ❌ 1. 过早优化

```cpp
// ❌ 还没测量就开始优化
int sum = 0;
for (int i = 0; i < n; ++i) {
    sum += data[i] * 2;  // 手动优化乘法
}

// ✅ 让编译器做
int sum = std::accumulate(data, data + n, 0);
```

### ❌ 2. 忽略算法复杂度

```cpp
// ❌ O(n²) 查找
for (int i = 0; i < n; ++i) {
    if (find(data, data + n, target) != data + n) {
        // ...
    }
}

// ✅ O(n) 哈希表
unordered_set<int> s(data, data + n);
if (s.count(target)) { /* ... */ }
```

### ❌ 3. 过度使用锁

```cpp
// ❌ 全局锁
std::mutex mtx;
{
    std::lock_guard<std::mutex> lock(mtx);
    map[key] = value;
}

// ✅ 使用并发数据结构
folly::AtomicHashMap<int, int> map(1024);
map.insert(key, value);
```

### ❌ 4. 忘记预分配

```cpp
// ❌ 多次重新分配
std::vector<int> vec;
for (int i = 0; i < 10000; ++i) {
    vec.push_back(i);  // 触发多次 realloc
}

// ✅ 预分配
std::vector<int> vec;
vec.reserve(10000);
```

### ❌ 5. 错误的数据结构

```cpp
// ❌ 需要查找用 list
std::list<int> l;
if (std::find(l.begin(), l.end(), target) != l.end()) { /* ... */ }

// ✅ 使用 unordered_set
std::unordered_set<int> s;
if (s.count(target)) { /* ... */ }
```

## 七、实战案例：优化日志系统

### 初始版本

```cpp
struct LogEntry {
    std::string message;
    std::string file;
    int line;
    std::string function;
    uint64_t timestamp;
};

std::vector<LogEntry> logs;

void addLog(const std::string& msg, const char* file,
            int line, const char* func) {
    logs.push_back({msg, file, line, func, getTimestamp()});
}
```

**性能**：1M 条日志 / 12.5 秒

### 优化 1：重组结构体

```cpp
struct LogEntry {
    // 热数据（频繁访问）
    uint64_t timestamp;
    int line;

    // 冷数据（少访问）
    folly::small_vector<char, 128> message;
    const char* file;
    const char* function;
};
```

**提升**：12.5s → 8.2s（1.5x）

### 优化 2：使用 Arena

```cpp
thread_local folly::SysArena arena;

void addLog(...) {
    auto* entry = new (arena.allocate(sizeof(LogEntry)))
        LogEntry(...);
    // ...
}
```

**提升**：8.2s → 3.5s（2.3x）

### 优化 3：批量写入

```cpp
class AsyncLogger {
    folly::EventBase evb_;
    folly::ProducerConsumerQueue<LogEntry*> queue_;

    void flush() {
        std::vector<LogEntry*> batch;
        while (queue_.read(item)) {
            batch.push_back(item);
        }
        writeBatch(batch);  // 批量写入
    }
};
```

**提升**：3.5s → 0.8s（4.4x）

### 总提升

**12.5s → 0.8s = 15.6x**

## 十、总结

### 性能优化的黄金法则

1. **测量优先**：不要猜测，用数据说话
2. **从上到下**：算法 > 数据结构 > 内存优化 > 微观优化
3. **局部性原理**：缓存友好 > 算法复杂度
4. **零拷贝**：避免不必要的内存复制
5. **异步优先**：I/O 密集型用事件驱动
6. **并发安全**：无锁 > 读写锁 > 互斥锁
7. **持续验证**：每次优化后重新测量

### 学习路径

**初级**（1-3 个月）：
1. 掌握基本数据结构（F14, small_vector）
2. 理解内存对齐和缓存
3. 使用 perf 分析性能

**中级**（3-6 个月）：
1. 深入理解 F14 实现
2. 掌握 Arena 和异步 I/O
3. 能够识别和优化热点

**高级**（6-12 个月）：
1. 理解无锁编程
2. 掌握 SIMD 优化
3. 能够设计高性能系统

**专家**（1 年+）：
1. 贡献 Folly 开源
2. 设计自己的优化库
3. 深入研究 CPU 微架构
