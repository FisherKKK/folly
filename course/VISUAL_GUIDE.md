```
│  │         ┌────────┐            │  10  │ 16  │             │
│  │         │  int0  │◄──┐        └──────────┘             │
```

## 4. Arena 内存分配器

### Arena 分配模式

```
┌─────────────────────────────────────────────────────────────┐
│                    SysArena                                  │
├─────────────────────────────────────────────────────────────┤
│                                                               │
│  Block 1 (4KB)                                               │
│  ┌────────────────────────────────────────────┐             │
│  │ Used:  [====][==][====][====][==]          │             │
│  │        ptr1  ptr2 ptr3  ptr4  ptr5         │             │
│  │ Free:           [=======================]  │             │
│  └────────────────────────────────────────────┘             │
│     ▲                                                      │
│     └── current_ (当前分配位置)                             │
│                                                               │
│  Block 2 (4KB)  (当 Block 1 满时分配)                       │
│  ┌────────────────────────────────────────────┐             │
│  │ Used:  [====][==]                          │             │
│  │        ptr6  ptr7                          │             │
│  │ Free:        [===========================] │             │
│  └────────────────────────────────────────────┘             │
│                                                               │
│  Block N (4KB)                                               │
│  ┌────────────────────────────────────────────┐             │
│  │ Used:  [====]                              │             │
│  │ Free:     [===============================]│             │
│  └────────────────────────────────────────────┘             │
│                                                               │
└─────────────────────────────────────────────────────────────┘

分配流程:
1. 检查当前 Block 是否有足够空间
2. 如果有，直接移动指针 (O(1))
3. 如果没有，分配新的 Block
4. Arena 析构时释放所有 Block (O(1))
```

### 性能优势

```
对比: 1000 次小内存分配 (平均 64 字节)

malloc/free:
┌──────┬──────┬──────┬──────┬──────┬──────┐
│alloc│alloc │alloc │...   │free  │free  │
│ 64B │ 64B  │ 64B  │      │ 64B  │ 64B  │
└──────┴──────┴──────┴──────┴──────┴──────┘
│
├─ 每次分配: 系统调用或锁竞争 (慢)
├─ 碎片化严重
└─ 总时间: ~85 μs

Arena:
┌──────────────────────────────────────┐
│ 一次性分配 Block (64KB)              │
│                                      │
│ [64B][64B][64B]...[64B] (1000个)   │
│  ▲                                   │
│  └── 只需移动指针                     │
│                                      │
│ 析构时一次性释放                      │
└──────────────────────────────────────┘
│
├─ 无系统调用
├─ 无碎片
└─ 总时间: ~9 μs (9.5x 提升)
```

## 6. AtomicHashMap 无锁查找

### Wait-Free 查找流程

```
┌─────────────────────────────────────────────────────────────┐
│              AtomicHashMap::find(key)                       │
├─────────────────────────────────────────────────────────────┤
│                                                               │
│  输入: key = "hello"                                          │
│                                                               │
│  1. 计算哈希值                                               │
│     hash("hello") = 0x3A5F...                                │
│     index = hash & capacityMask = 5                          │
│                                                               │
│  2. 线性探测 (Wait-Free)                                     │
│                                                               │
│     ┌───────────┬───────────┬───────────┬───────────┐       │
│     │index=5    │index=6    │index=7    │index=8    │       │
│     ├───────────┼───────────┼───────────┼───────────┤       │
│     │key="world"│key="hello"│EMPTY      │key="test" │       │
│     │value=42   │value=99   │           │value=7    │       │
│     └───────────┴───────────┴───────────┴───────────┘       │
│       │                                                    │
│       │ 比较失败                                           │
│       ▼                                                    │
│     ┌───────────┐                                          │
│     │index=6    │ ◄── 匹配！                               │
│     ├───────────┤                                          │
│     │key="hello"│                                          │
│     │value=99   │                                          │
│     └───────────┘                                          │
│                                                               │
│  3. 返回 value 指针                                         │
│     return &entry.value_;  // Wait-Free!                   │
│                                                               │
│  时间复杂度: O(1) 平均（无锁）                                │
│                                                               │
└─────────────────────────────────────────────────────────────┘
```

### CAS 循环 (插入)

```
插入 key="new", value=123

1. 找到空槽位 (index=9)

   ┌──────────┬──────────┬──────────┬──────────┐
   │ ...      │index=9   │ ...      │          │
   │          ├──────────┤          │          │
   │          │EMPTY     │          │          │
   │          │          │          │          │
   └──────────┴──────────┴──────────┴──────────┘

2. CAS 原子操作

   do {
       // 读取当前状态
       expected = EMPTY;
       desired = insert("new", 123);

       // 原子替换
   } while (entries_[9].key_.compare_exchange_strong(
               expected,      // 如果当前是 EMPTY
               desired,       // 则替换为 desired
               memory_order_release,
               memory_order_relaxed));

   ▼ 成功！插入完成

3. 处理竞争

   如果 CAS 失败（另一个线程抢先插入）:
   ┌──────────┬──────────┐
   │index=9   │          │
   ├──────────┤          │
   │"other"   │          │
   │value=456 │          │
   └──────────┴──────────┘

   → 继续探测下一个槽位 (index=10)
```

```

       │         │         │         │

       │    └─────────┘   │         │

       │         │    线程 C: │      │
       │         │    分配 A  │      │
       │         │         │         │

       │         │         │         │
       │    成功! │    ❌ 错误!       │
       │         │ (A 已被改写)       │

解决方案: Hazptr 保护
       │         │         │         │
线程 A: │         │ 保护 PTR │         │
       │         ▼         │         │
       │    ┌─────────┐   │         │

       │         │    (推迟释放)│    │
       │         │         │         │
       │         │    检查 Hazptr     │
       │         │    A 被保护 →      │
       │         │    等待...         │

       │  成功!   │         │         │
```

### 优化决策树

```
性能问题
    │
    ▼
是否是热点函数?
    │
    ├─ 否 → 不是瓶颈，无需优化
    │
    ▼ 是
    │
是否 CPU 密集?
    │
    ├─ 否 (I/O 密集) → 优化 I/O (异步、缓存)
    │
    ▼ 是
    │
缓存未命中率高?
    │
    ├─ 是 → 优化内存布局
    │      - 紧凑数据结构
    │      - 缓存行对齐
    │      - 避免伪共享
    │
    ▼ 否
    │
分支预测失败率高?
    │
    ├─ 是 → 优化分支
    │      - FOLLY_LIKELY/UNLIKELY
    │      - 分支less 算法
    │      - 查表法
    │
    ▼ 否
    │
是否可并行?
    │
    ├─ 是 → 并行化
    │      - 多线程
    │      - SIMD
    │
    ▼ 否
    │
算法级优化
    - 更优算法
    - 减少内存分配
    - 避免拷贝
```
